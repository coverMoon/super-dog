# 2026-06-26 blackW Jun25 楼梯开关对照结果记录

## 1. Jun25_22-05-27_ 与 Jun25_22-07-32_ 对照

两组都从 `Jun06_18-32-14_` resume，训练 4096 env、1000 iter，step 范围为 27001 到 28000。两者配置只差一个开关：

- `Jun25_22-05-27_`：当前 A 组，`stairs_use_simple_lift = True`，`stairs_use_threshold_spin = False`。
- `Jun25_22-07-32_`：当前 B 组，`stairs_use_simple_lift = True`，`stairs_use_threshold_spin = True`。

两组都已经删除 `stairs_run_still`，并使用新命名 `wheel_obstacle_unloaded_lift`。

末 500 iter 均值看，A 组明显更稳：`mean_reward` 约 67.99，`mean_episode_length` 约 980.7，`terrain_level` 约 5.58；B 组分别约 53.32、967.8、5.53。B 组 tracking、progress 和 `rew_wheel_obstacle_lift` 均略低，同时 `rew_wheel_obstacle_spin` 更重。

B 组主要问题是训练稳定性明显变差：末 500 iter 的 `rew_smoothness` 约 -0.223，显著重于 A 组约 -0.090；`rew_torques` 约 -0.709，重于 A 组约 -0.442；`rew_dof_pos_limits` 约 -0.112，重于 A 组约 -0.053；`rew_base_height` 也更差。B 组 value loss 末 500 iter 均值约 81.5，最大到 1268，learning rate 被压到 1e-5，并在 27799 附近出现 `mean_reward = -425.76` 的异常尖峰。A 组 value loss 末 500 iter 约 0.35，整体稳定。

结论：当前更认可 A 组，即只保留上楼梯 simple lift，不启用楼梯 hard-threshold spin。B 组的 `stairs_use_threshold_spin` 虽然目标是恢复 Jun06 风格硬阈值 anti-spin，但这轮看会引入强不稳定和动作/力矩恶化，不建议继续作为主线。

后续建议：先用 A 组做 sim2sim 观察，重点看上楼梯前轮触台阶后的前顶/前挤、楼梯通过率、高墙姿态和 `rew_wheel_obstacle_unloaded_lift` 量级。若仍需要处理楼梯空转，优先在当前连续 spin 逻辑上小幅调 `slip_speed_sigma`、`progress_speed_sigma` 或 scale，而不是回到硬阈值分支。

## 2. sim2sim 复查后的下一轮判断

sim2sim 观察：`Jun25_22-05-27_` 和 `Jun25_22-07-32_` 的高墙翻越能力都还不够强，可能和从 Jun06 checkpoint 只续训 1000 iter 有关；同时 `Jun25_22-07-32_` 的姿态和翻越丝滑程度反而更好一些，说明 B 组虽然 TensorBoard 上更不稳，但 hard-threshold spin 可能带来了更好的接触节奏或动作先验。

需要注意：当前 `stairs_use_threshold_spin` 只在上楼梯 type 3 中把连续 spin 替换成硬阈值逻辑，高墙 type 9 仍走连续 spin。因此 B 组高墙更丝滑更可能是共享 policy 动作先验的间接迁移，而不是高墙 reward 公式直接改变。

下一轮建议先接着训两条线：一条保留 A 组配置继续训，用于判断高墙能力是否只是训练时间不足；另一条从 B 组继续，保留 hard-threshold spin 方向，并在服务器实际续训配置中将 `spin_threshold` 从 8.0 降到 5.0。这个调整目标是让楼梯触障空转更早被惩罚，减少轮子持续空转带来的硬顶和接触节奏拖沓，尝试保留 B 组较好的姿态/翻越丝滑程度。

注意：当前本地工作区暂未同步该 `spin_threshold = 5.0` 改动，本条仅记录服务器续训参数选择。后续复查时需要把新 run 与 `Jun25_22-07-32_` 区分开，不要误认为仍是原始阈值 8.0。

若两条线继续训练后高墙仍弱，再优先做高墙局部参数，而不是先继续加全局姿态约束：可考虑放松 `wheel_obstacle_unloaded_lift`，或增加高墙 lift 的 active time / clearance，使真正触墙轮和必要的身体翻越动作有更多空间。

## 3. Jun26_00-36-33_ 与 Jun26_00-38-18_ 续训结果复查

两组均训练到 31000 iter。`Jun26_00-36-33_` 从 `Jun25_22-05-27_` 继续，保持 `stairs_use_simple_lift = True`、`stairs_use_threshold_spin = False`；`Jun26_00-38-18_` 从 `Jun25_22-07-32_` 继续，保持 `stairs_use_simple_lift = True`、启用 `stairs_use_threshold_spin = True`，并确认服务器配置中 `spin_threshold` 已从 8.0 降到 5.0。

末 500 iter 均值看，两组 TensorBoard 稳定性已经接近：`Jun26_00-36-33_` 的 `mean_reward` 约 71.92、`mean_episode_length` 约 983.7、`terrain_level` 约 5.61；`Jun26_00-38-18_` 分别约 71.57、981.9、5.80。B 线相对父 run 改善很大，之前的 value loss 爆炸基本消失，末 500 iter `value_function` 约 0.35，`rew_smoothness`、`rew_torques`、`rew_dof_pos_limits` 也恢复到和 A 线同一量级。

当前判断：B 线不再像上一轮那样明显不可用，`spin_threshold = 5.0` 后 hard-threshold spin 至少在训练曲线上被稳定住了，并带来更高的地形等级；但它的 `cmd_curr_yaw_range` 末段只有 1.7，而 A 线为 2.5，同时 B 线 `tracking_ang_vel`、`tracking_lin_vel_y`、`smoothness` 和 `wheel_lateral_clearance` 略弱。也就是说 B 线可能更偏向地形通过，yaw 课程和横向/转向跟踪暂时落后。

后续建议：不要只凭 TensorBoard 直接切主线。优先对两组都做 sim2sim，重点比较高墙通过率、上楼梯是否还前顶、转向/yaw 指令下是否发散以及轮子触障空转。如果 B 线实际动作确实更丝滑且 yaw 不明显变差，可以继续沿 B 线小步观察；若 sim2sim 中转向、横移或姿态稳定性差，主线仍优先保留 A 线。

## 4. sim2sim 实际观察补充

sim2sim 后两组各有优劣。A 线整体更均衡，平地运动能力更好，高墙大部分时候可以成功但偶尔失败；主要问题在上楼梯时有时轮子持续空转，导致卡住。B 线轮子空转现象有所好转，但动作幅度更大，旋转时姿态不够好。

结合实现看，A 线的连续 spin 惩罚更温和，保留了较好的平地和 yaw 能力，但在楼梯触障且前进不足时，对“长时间空转”约束可能不够强；B 线 hard-threshold spin 能明显压住楼梯空转，但也容易诱导更激进的脱困动作，并间接牺牲 yaw/转向姿态。后续更适合做局部折中：以 A 线为主线，单独增强上楼梯卡住时的 anti-spin，而不是直接采用 B 线整套 hard-threshold 风格。若继续研究 B 线，建议增加 yaw/转向门控，只在低 yaw、正向上楼梯卡住时启用硬阈值惩罚，避免影响旋转动作。

## 5. A 线楼梯连续 anti-spin 小幅增强

按优先方案先做一轮简洁实验：本地配置同步为 A 线方向，`stairs_use_simple_lift = True`、`stairs_use_threshold_spin = False`，并新增 `wheel_obstacle_spin.stairs_continuous_scale = 1.5`。实现上只在上楼梯 terrain type 3 中将连续 `wheel_obstacle_spin` 惩罚乘以该倍率，高墙和平地仍使用原连续逻辑，不引入额外复杂门控。

目标是保留 A 线较好的平地/yaw/整体均衡能力，同时加强楼梯触障且前进不足时对持续轮子空转的抑制。观察重点：上楼梯卡住空转是否减少，转向姿态是否仍接近 A 线，高墙偶发失败是否恶化，以及 `rew_wheel_obstacle_spin`、`rew_smoothness`、`rew_torques` 是否出现明显变重。

## 9. run_still 从 y/yaw 硬阈值改为衰减

针对 sim2real 中平地 x+yaw 混合指令姿态危险、轮子因装配误差逐渐并拢的问题，本次将 `_reward_run_still` 的 y/yaw 门控从硬阈值改为连续衰减。x 方向仍要求 `abs(cmd_x) > run_still_x_threshold` 才启用；启用后，y/yaw 不再通过 `run_still_y_threshold/run_still_yaw_threshold` 一刀切关闭，而是复用 `hip_default` 的 y/yaw 参考和衰减参数，随 `abs(cmd_y)`、`abs(cmd_yaw)` 增大逐步降低到 `hip_default_cmd_min_scale`。

目标是在 x+yaw 混合指令下仍保留一部分非轮关节回默认姿态的约束，抑制持续行走时髋部慢性变形和支撑宽度丢失；同时避免像简单放大 yaw 阈值那样在大 yaw 下过强压制转向动作。观察重点：sim2real 平地 x+yaw 是否更不易侧翻，轮子并拢是否减轻，TensorBoard 中 `rew_run_still` 是否变重，`tracking_ang_vel`、`rew_smoothness`、`rew_torques` 和楼梯/高墙动作是否被压硬。

## 10. hip_default 配置块整理

将 `_reward_hip_default` 的可调参数从 `rewards` 顶层整理到独立的 `rewards.hip_default` 配置块：`cmd_min_scale`、`y_ref`、`yaw_ref`、`y_scale`、`yaw_scale`。数值保持与原先一致，不改变训练目标。`_reward_hip_default` 和新的 run_still 衰减逻辑都改为复用同一个 command scale helper，避免后续调髋默认姿态衰减时出现两套参数不一致。

随后进一步将 run_still 的衰减参数独立为 `rewards.run_still` 配置块，字段同样为 `cmd_min_scale/y_ref/yaw_ref/y_scale/yaw_scale`。当前数值先与 `hip_default` 保持一致，因此训练行为不变；后续可以单独调 run_still 在 x+yaw 混合指令下的保留强度，而不影响髋关节默认姿态项。
