# 2026-06-03 blackW 地形高墙生成调整记录

## 1. 高墙地形混合薄墙与厚墙，并支持单块多墙

针对当前 heightfield/trimesh 水平分辨率为 0.1m 时，原计划 3cm 高墙厚度会被离散化吞掉的问题，本次只在 legged_gym/legged_gym/utils/terrain.py 中调整高墙生成逻辑，不在 blackW config 中新增显式参数。

问题分析：

- heightfield 高度值位于网格顶点，不是单元格；
- 0.10m 厚墙在 0.10m horizontal scale 下如果只抬高 1 行采样点，转成 trimesh 后仍接近一条零厚度尖脊；
- 要形成约 10cm 顶部平台，至少需要抬高 2 行相邻顶点。

最终改动：

- 高墙地形默认每个 terrain tile 生成 3 堵墙，而不是固定 1 堵；
- 高墙距离不再随机采样，改为从中心前方固定起始距离开始，按固定 spacing 排列；
- 默认起始距离为 1.2m，默认间距为 0.8m，保证机器人出生地附近没有高墙；
- 厚度默认按 width_options 顺序循环，默认 0.0m / 0.10m / 0.0m，确保同一块地形内能看到薄墙和厚墙混合；
- 0.0m 厚度继续使用 1 行高顶点，保留尖脊/薄墙效果；
- 非零厚度墙改为至少 2 行高顶点，例如 0.10m 厚度在 0.10m 分辨率下形成两行高顶点之间的约 10cm 顶部平台；
- 在 terrain.py 中保留 high_wall_width_options / high_wall_num_walls / high_wall_start_distance / high_wall_spacing 参数入口，后续如需可由具体任务 cfg 覆盖。

预期观察：

- 高墙列不再只有单一障碍，tile 内会有连续越障压力；
- 混合薄墙/厚墙后，策略同时见到尖锐接触和一格厚实体墙两类情况；
- 固定间距比随机采样更容易复现实验现象。

风险和回退：

- 若越障失败率过高，可调大 high_wall_spacing 或减少 high_wall_num_walls；
- 若厚墙仍显示过窄，可继续把 high_wall_width_options 的厚墙项调到 0.2m，对应更宽顶部平台。


## 2. blackW 主线 base_height 改为身下小范围采样，并对高墙列按平地处理

本次只调整 legged_gym/legged_gym/envs/blackW/blackW_env.py 中的 _reward_base_height，不新增 config 参数。

改动目标：

- 当前主线 blackW 不再用整片 measured_heights 的均值计算 base_height，而是复用 BlackEnv 的 _get_under_body_height_samples，只采样机器人身下小范围高度点；
- 对高墙地形列做特殊处理：通过 terrain_types / num_cols 和 terrain_proportions 判断高墙列，在这些 env 中把地形参考高度视为 0，只计算机身相对平地的高度误差；
- base_height 误差从 square 改回 abs，与旧版 blackW 继承的 LeggedRobot base_height 逻辑一致，减少墙体采样误差造成的异常尖峰。

预期观察：

- 普通地形上 base_height 奖励更接近旧版身下采样逻辑；
- 高墙地形上翻墙时，墙顶被采到导致的 base_height 假性偏低/偏高会被抑制；
- Jun03_14-12-48_ 中 5000 轮附近 base_height 尖峰导致的 value loss 抖动应有所缓解。

风险和回退：

- 高墙列会完全忽略墙体高度对 base_height 的影响，翻墙姿态主要依赖其他越障、接触和稳定性奖励约束；
- 若后续发现高墙上机身高度过低，可回退为只在高墙列对 terrain_height 做 clamp，而不是直接置零。


## 3. 修正高墙默认排列，避开出生中心高度统计窗口

Jun03_14-33-58_ 训练中仍出现 base_height 与 lin_vel_z 同步尖峰。分析后发现当前高墙默认排列为 num_walls=8、start_distance=-2.5、spacing=1.2，会在中心附近约 -0.1m 生成一堵墙；而 terrain env_origin_z 使用出生中心前后约 1m 区域的最高点计算，因此高墙会把机器人初始高度整体抬高，随后落回平地时触发较大的竖直速度与 base_height 惩罚。

本次只调整 terrain.py 中 high_wall_terrain 调用处的默认入口参数：

- high_wall_num_walls 默认从 8 改为 3；
- high_wall_start_distance 默认从 -2.5m 改为 1.2m；
- high_wall_spacing 维持 1.2m；
- 参数入口仍通过 getattr 保留，后续任务 cfg 可覆盖。

预期观察：

- 高墙不会落入出生中心 [-1m, +1m] 的 env_origin_z 统计窗口；
- 高墙地形上的 init_state 高度不再被墙高抬升；
- base_height 与 lin_vel_z 的偶发极端尖峰应明显减少。

风险和回退：

- 单块地形有效墙数减少，越障密度低于之前的 8 墙排列；
- 若后续仍希望更密，可在保持 start_distance >= 1.2m 的前提下减小 spacing 或增加 num_walls，但需要确认最后生成的墙不会回到出生窗口内。


## 4. 高墙地形命令采样只保留 x 指令

为降低高墙越障时由横向速度和 yaw 指令造成的斜向撞墙、转向撞墙和异常接触，本次在 blackW 主线命令重采样逻辑中加入高墙地形门控，不新增显式 config 字段。

改动内容：

- 在 BlackWEnv 中新增 _get_high_wall_env_mask，统一根据 terrain_types / num_cols 和 terrain_proportions 判断高墙 env；
- _resample_commands 中，高墙 env 仍正常采样 x 指令，但将 y 指令乘 high_wall_y_command_scale，默认 0.0；
- 非 heading 模式下，高墙 env 的 yaw 指令乘 high_wall_yaw_command_scale，默认 0.0；
- heading 模式下，在 heading yaw 后处理之后再次对高墙 env 的 yaw 指令做同样缩放，避免被 heading 逻辑覆盖；
- _reward_base_height 复用同一个高墙 mask，避免高墙列判断逻辑分散。

预期观察：

- 高墙地形主要训练前向越障，不再混入侧向或转向越障；
- 高墙相关的 lin_vel_z、base_height、value loss 偶发尖峰应进一步减少；
- y/yaw 课程学习不会被高墙 env 的困难样本额外拖累，因为高墙 env 上 y/yaw 指令默认为 0，会被课程统计中的 cmd_min 过滤掉。

风险和回退：

- 高墙地形不再训练横向或旋转越障能力，策略在真实高墙前斜向接近时泛化可能较弱；
- 若后续希望保留少量扰动，可在任务 cfg 中设置 high_wall_y_command_scale 或 high_wall_yaw_command_scale 为 0.2-0.3。


## 5. 将高墙专用命令门控扩展为按地形类别配置的 range 采样

为支持“越障/困难地形主要训练 x 指令，简单地形正常训练 x/y/yaw”的框架，本次将 blackW 主线中高墙专用的 y/yaw 指令处理扩展为通用的地形类别命令采样机制。

配置入口：

- 在 commands 下新增 terrain_command_sampling；
- difficult_terrain_types 用地形类型索引配置困难地形集合；
- 简单地形不额外设置，直接跟随全局 command_ranges；
- 困难地形通过 difficult_lin_vel_y 和 difficult_ang_vel_yaw 直接设置采样范围，例如 [-0.3, 0.3]，不再使用 scale 缩放形式。

当前默认：

- difficult_terrain_types = [3, 4, 5, 6, 7, 8, 9]，对应楼梯上、楼梯下、乱石/障碍、梅花桩、沟壑、木板桥、高墙；
- difficult_lin_vel_y = [0.0, 0.0]；
- difficult_ang_vel_yaw = [0.0, 0.0]。

实现逻辑：

- 根据 terrain_types / num_cols 与 terrain_proportions 将 env 映射回地形类型 id；
- _resample_commands 中，简单地形继续按全局 lin_vel_y / ang_vel_yaw 范围采样；
- 困难地形用 difficult_lin_vel_y / difficult_ang_vel_yaw 覆盖 y/yaw 采样；
- heading_command=True 时，先按 heading 计算 yaw 指令，再对困难地形 clamp 到 difficult_ang_vel_yaw 范围；
- base_height 的高墙特殊处理复用同一套地形类型 id 判断。

预期观察：

- 困难地形不再混入大 y/yaw 指令，terrain curriculum 更关注前向通过能力；
- 简单地形仍保留完整 y/yaw 训练，不牺牲平地转向和横移能力；
- 后续可直接通过 range 调参，避免 scale 形式带来的换算负担。

风险和回退：

- 如果困难地形上完全不训练 y/yaw，真实斜向接近障碍的泛化会弱；
- 可以把 difficult_lin_vel_y / difficult_ang_vel_yaw 放宽到小范围，例如 [-0.2, 0.2] 或 [-0.3, 0.3]，逐步恢复扰动。


## 6. 困难地形不参与 y/yaw 命令课程学习

前一版按地形类别配置 y/yaw 采样 range 后，如果困难地形 range 为 [0.0, 0.0]，y/yaw 样本会因为 cmd_min 被课程统计过滤；但如果后续把困难地形 range 放宽到 [-0.3, 0.3]，困难地形仍会重新参与 y/yaw 课程学习。

本次进一步明确课程统计边界：

- x 课程仍统计所有地形，包含困难地形；
- y 课程只统计非困难地形 env；
- yaw 课程只统计非困难地形 env；
- 困难地形上的 difficult_lin_vel_y / difficult_ang_vel_yaw 只用于训练扰动，不推动全局 y/yaw command range 扩张。

预期观察：

- 越障/困难地形不会把 y/yaw 课程推快，也不会拖低 y/yaw 课程评分；
- y/yaw 课程主要由平地和斜坡等简单地形决定；
- 可在困难地形保留小范围 y/yaw 扰动，而不影响全局课程学习节奏。


## 7. 高墙地形削弱 base_height 惩罚

高墙地形中虽然已将 terrain_height 按平地处理，避免墙高被采样进 base_height，但翻墙时机身真实抬高仍会被 base_height 的双侧 abs 误差惩罚。为减少 base_height 对翻墙动作的干扰，本次只在 blackW_env.py 的 _reward_base_height 内加入局部系数，不新增 config 参数。

改动内容：

- 普通地形 base_height 误差保持 abs(base_height - target)；
- 高墙地形仍使用相对平地高度 base_z - 0；
- 高墙地形上的 base_height error 额外乘 high_wall_base_height_scale = 0.25；
- 该系数只保留在 reward 函数内部，不写入 config。

预期观察：

- 高墙翻越时 base_height 负奖励尖峰降低；
- 普通地形上的站高约束不变；
- 高墙地形主要由越障、接触、速度和稳定性项约束，而不是强行压住机身高度。

风险和回退：

- 高墙地形上机身高度约束变弱，若出现过度抬身或姿态松散，可将系数从 0.25 上调到 0.5。
