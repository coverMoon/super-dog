# 2026-06-04 blackW 训练异常分析与调整记录

## 1. 下楼梯前轮落下后掉头回走问题分析与抬轮奖励调整

现象：最新训练 `Jun04_15-02-16_` 在 sim2sim/play 中下楼梯时，即使 x 指令持续向前，前轮落下后策略会快速掉头并往回走。

日志分析：

- `Jun04_15-02-16_` 从 `Jun03_21-57-11_` 继续训练；
- `rew_wheel_obstacle_lift` 均值从约 0.37 上升到约 1.03，但 `terrain_level` 均值从约 3.84 下降到约 2.95；
- 说明策略更容易获得抬轮奖励，但真实通过地形的能力下降；
- 当前速度跟踪和 progress 都基于机体系速度，机器人掉头后沿自身 x 方向前进仍可能获得 x tracking/progress 奖励；
- 下楼梯时前轮落到低一级后，前方 heightfield 采样可能采到上一级台阶边缘，`wheel_obstacle_lift` 会鼓励重新抬向高处，诱导掉头或回到台阶上方。

本次改动：

- 保持 `wheel_obstacle_lift` reward scale 为 1.2，但通过下楼梯地形门控避免该项在下楼梯中诱导掉头；
- 在 `_reward_wheel_obstacle_lift` 中识别 terrain type 4（楼梯下），下楼梯地形上 `down_stairs_lift_scale = 0.0`，不再给抬轮奖励；
- 上楼梯、高墙、乱石等其他地形仍保留抬轮奖励逻辑。

预期观察：

- 下楼梯时策略不再通过抬轮奖励驱动掉头回到高处；
- `rew_wheel_obstacle_lift` 均值应下降，`terrain_level` 不应继续因该项升高而下跌；
- 需要重点观察下楼梯地形的实际通过方向、`tracking_lin_vel_x`、`progress`、`terrain_level`。

风险和后续方向：

- 下楼梯完全关闭抬轮奖励后，如果前轮卡边缘，可以改为小系数如 0.2，而不是 0.0；
- 若仍出现掉头，下一步应增加世界方向/heading 保持约束，因为当前 body-frame x tracking 无法区分“向前走”和“掉头后向前走”。
