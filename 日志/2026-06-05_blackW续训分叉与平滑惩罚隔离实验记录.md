# 2026-06-05 blackW 续训分叉与平滑惩罚隔离实验记录

## 1. `Jun04_21-53-59_` 与 `Jun04_21-57-42_` 训练分叉分析

现象：`Jun04_21-53-59_` 与 `Jun04_21-57-42_` 的最终训练配置差异很小，主要只有续训来源、`action_rate` 和 `smoothness` 不同，但两条曲线差异很大。`Jun04_21-53-59_` 在续训中后段出现明显崩溃，而 `Jun04_21-57-42_` 基本稳定。

配置追溯：

- `Jun04_21-53-59_` 从 `Jun03_21-57-11_` 继续训练，目标配置为 `action_rate = -0.1`、`smoothness = -0.02`；
- `Jun04_21-57-42_` 从 `Jun04_11-13-57_` 继续训练，目标配置为 `action_rate = -0.05`、`smoothness = -0.01`；
- 两个父 run 都从 `Jun02_22-30-50_` 分叉，但父 run 的 reward 形态不同：`Jun03_21-57-11_` 为 `action_rate = -0.08`、`smoothness = -0.015`、`wheel_obstacle_lift = 1.0`；`Jun04_11-13-57_` 为 `action_rate = -0.05`、`smoothness = -0.01`、`wheel_obstacle_lift = 1.5`；
- `Jun04_21-53-59_` 的保存 diff 还包含下楼梯地形关闭抬轮奖励的 `blackW_env.py` dirty patch，`Jun04_21-57-42_` 时该改动已进入提交基线，dirty diff 只剩 `action_rate/smoothness` 调整。

关键曲线：

- `Jun04_21-53-59_` 在 step 10050 附近仍健康：`mean_reward` 约 65.4，`terrain_level` 约 3.91，`value_loss` 约 0.121；
- 到 step 11000，`value_loss` 已升到约 67.9，`mean_reward` 降到约 24.5；
- step 11500 到 12000 左右进入失稳区间，`mean_reward` 降到约 -229 到 -248，`value_loss` 升到约 372 到 670；
- 后段 `terrain_level` 从高点约 6.15 下滑到最低约 1.79，最终约 2.84；`Policy/mean_noise_std` 从约 0.35 持续升到约 0.76；
- 同期 `rew_smoothness`、`rew_torques`、`rew_base_height` 明显恶化，其中 `rew_smoothness` 最低约 -12.03，`rew_base_height` 最低约 -9.68；
- `Jun04_21-57-42_` 则保持稳定：`mean_reward` 基本在 55 到 60，`terrain_level` 稳定在 6.0 左右，末尾 `value_loss` 约 0.134，`mean_noise_std` 从约 0.449 略降到约 0.437。

判断：

- `Jun04_21-53-59_` 不是单纯因为更强 `action_rate/smoothness` 惩罚导致 reward 略低，而是 PPO 训练状态明显失稳；
- 更可能的触发条件是续训初值与新 reward 形态不兼容：从较保守、抬轮奖励较低的 `Jun03_21-57-11_`，直接切到更强 action/smoothness 惩罚、`wheel_obstacle_lift = 1.2`、下楼梯关闭抬轮奖励后，策略先快速冲到高地形，再在高地形压力下出现动作抖动、力矩和高度项恶化，最终 value loss 和探索噪声一起放大；
- `Jun04_21-57-42_` 的父策略 `Jun04_11-13-57_` 已经适应弱 action/smoothness 惩罚和更强抬轮奖励，因此继续训练时冲击小得多。

当前隔离实验：

- 正在跑 `Jun03_21-57-11_ + action_rate = -0.05, smoothness = -0.01`，用于确认 `Jun04_21-53-59_` 的崩溃是否主要由强 action/smoothness 惩罚触发；
- 原计划另一个对照 `Jun04_11-13-57_ + action_rate = -0.1, smoothness = -0.02` 暂时不跑；
- 若当前实验稳定，优先说明 `Jun03_21-57-11_` 父策略并非不可续训，强 action/smoothness 惩罚是主要风险；若仍崩，则说明父 checkpoint 与下楼梯抬轮关闭、`wheel_obstacle_lift = 1.2` 的组合本身就有较大失稳风险。

## 2. 困难地形 heading command 与简单地形 yaw 课程学习并行

动机：`Jun04_21-57-42_` 从可用性上更稳定，但全局 `heading_command = True` 会让所有地形都从 heading error 生成 yaw rate，简单地形不再直接采样 `ang_vel_yaw`，导致 yaw 指令课程学习缺失。为了避免困难地形通过掉头/绕行混分，同时保留简单地形 yaw-rate 训练，本次将 heading command 改为可按地形生效。

本次改动：

- 在 `BlackWCfg.commands` 中新增 `heading_command_difficult_only = True`；
- `heading_command = True` 且 `heading_command_difficult_only = True` 时，只在 `terrain_command_sampling.difficult_terrain_types` 对应地形上启用 heading command；
- 简单地形继续采样 `ang_vel_yaw`，并继续参与 yaw command curriculum；
- 困难地形仍使用 heading 采样到 `commands[:, 3]`，再在 physics step 中转换为 `commands[:, 2]`，并继续通过 `difficult_ang_vel_yaw` clamp 限制最大 yaw rate；
- 若后续把 `heading_command_difficult_only` 关掉，则恢复旧的全局 heading command 行为。

预期观察：

- TensorBoard 中应重新出现/持续更新 `Episode/cmd_curr_yaw_range` 与 `Episode/cmd_curr_yaw_score`；
- 简单地形上的 `tracking_ang_vel` 不应明显退化，`ang_vel_yaw` range 应能随课程扩展；
- 楼梯上/下、高墙等困难地形应继续受 heading 约束，减少掉头后沿机体系 x 前进混分；
- 需要同时观察 `terrain_level`、`rew_progress`、`rew_tracking_ang_vel`、`cmd_curr_yaw_range`，避免 yaw curriculum 扩太快反过来伤害越障。

风险与回退：

- 同一策略会同时看到直接采样的 yaw-rate command 和由 heading controller 生成的 yaw-rate command；低层输入都是 `commands[:, 2]`，理论上可接受，但可能增加命令分布混合难度；
- 如果困难地形仍出现绕行混分，可进一步把 `difficult_ang_vel_yaw` 收紧，例如从 `[-0.5, 0.5]` 调到 `[-0.3, 0.3]`；
- 如果简单地形 yaw 能力恢复但越障下降，可按 terrain type + level 细化 heading mask，而不是只按 type 区分。

## 3. 简单地形 heading/yaw-rate 按概率随机采样

动机：只让简单地形全量 yaw-rate 训练仍可能拖慢 terrain curriculum 的平均升级。由于地形课程学习是 per-env 独立升级/降级，而 TensorBoard 记录的是全体 env 的平均 `terrain_level`，简单地形中保留一部分 heading command 可以提供更稳定的通过样本，同时其余样本继续训练 yaw-rate。

本次改动：

- 新增 `simple_heading_command_prob = 0.3`；
- 困难地形仍固定使用 heading command；
- 简单地形在每次 `_resample_commands()` 时按 `simple_heading_command_prob` 随机选择 heading 或 yaw-rate；
- 随机结果保存到 `heading_command_env_mask`，在一个 command resampling interval 内保持不变；
- yaw curriculum 只收集当前 mask 下实际走 yaw-rate 的简单地形 env，避免 heading 生成的 yaw-rate 混入 yaw 指令课程学习。

预期观察：

- 相比简单地形全量 yaw-rate，`terrain_level` 平均值应更稳；
- `cmd_curr_yaw_range/cmd_curr_yaw_score` 仍应正常出现并更新；
- 如果 yaw 能力恢复过慢，可把 `simple_heading_command_prob` 从 0.3 降到 0.2；如果 terrain_level 被 yaw 训练拖住，可升到 0.4 或 0.5。
