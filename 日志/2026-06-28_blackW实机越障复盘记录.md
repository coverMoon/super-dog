## 1. Jun27_17-07-17_ 与 Jun27_17-09-43_ sim2real 观察

实机测试与 sim2sim 基本一致。`Jun27_17-07-17_` 上楼梯仍会在中段卡住，典型场景是前轮和后轮同时抵着台阶，随后可能出现轮子不转或持续空转。`Jun27_17-09-43_` 相对更容易抬腿，高墙前腿抬得更高，但楼梯卡住没有完全消失，高墙后腿有时仍会卡住。

当前判断：这不是单纯 sim2sim 可视化误差，而是策略学到的接触处理模式本身存在缺口。`17-07-17` 的 `stairs_continuous_scale = 1.6` 没有解决问题，说明楼梯中段不是只靠更强 anti-spin 就能处理；现象同时包含“不转”和“空转”，前者更像姿态/动作空间或接触几何卡死，后者才对应空转惩罚不足。继续简单加大 spin 惩罚可能压低轮子输出，使“不转”更明显。

`17-09-43` 证明更高的 `clearance_margin` 和 `over_lift_margin` 能释放抬腿高度，尤其改善高墙前腿动作；但后腿卡住说明剩余瓶颈不只是目标高度，而是最后一条腿越过障碍时缺少持续推进/滚过障碍的引导。当前 `wheel_obstacle_lift` 主要奖励触障后短窗口内抬到目标高度，`wheel_obstacle_spin` 主要惩罚接触且前进不足时的空转；两者都没有明确奖励“轮子已经接触/抬起后继续向前越过障碍”的过程。

后续优先方向应从“继续提高全局抬腿高度”转向更局部的接触后进度设计：楼梯侧重点是前后轮同时抵台阶时的重新推进和脱困，高墙侧重点是后腿/最后一轮的持续前向滚过。下一步仍建议保持改动小，优先做一到两个单变量实验，而不是同时加大 lift、spin 和稳定性约束。

## 8. Jun28_12-57-26_ 与 Jun28_12-59-21_ sim2real 上楼梯观察

当前 sim2real 只测试了上楼梯。`Jun28_12-57-26_` 与 `Jun28_12-59-21_` 的实际差异不大，两者仍会在楼梯中段卡住：典型表现是前轮和后轮都碰到楼梯沿，随后持续空转，但没有明显抬腿脱困。

结合 reward 实现，当前怀疑楼梯中段瓶颈不只是 clearance 或 spin 强度。`wheel_obstacle_lift` 对每个轮子独立触发 timer/target，并把四个轮子的 lift reward 直接加和；在楼梯上又使用 `stairs_use_simple_lift = True`，不会通过 high-wall active time 建立额外阶段区分。当前奖励没有表达“前轮先抬/越过，后轮支撑推进，随后后轮再抬”的时序，也没有对前后轮同时顶住台阶时的脱困过程给出明确正向引导。因此当前加大 `clearance_margin` 或 `wheel_obstacle_spin` 只能缓解一部分卡边/空转问题，不能根治前后轮同时受阻时策略不知道如何分工的问题。

后续方向应从单纯加 lift height 或 anti-spin 转向楼梯中段多轮接触脱困设计。优先考虑先做诊断统计：在 type 3 楼梯上记录同时触障轮数、各轮 lift timer、轮子高度进度、base forward speed 和 wheel surface speed，确认卡住时是否四轮/前后轮同时 active 且 lift reward 没有转化为前向进度。若确认该模式，再考虑楼梯专用 reward：例如在多轮触障且前进不足时限制 lift reward 的加和方式、引入前/后轮分阶段或 top-k 抬轮奖励，或增加“触障后实际前向越过台阶”的正向进度项，而不是继续简单提高全局 clearance 或 spin 惩罚。

## 9. wheel_obstacle_lift 多轮协调聚合实验

针对实机上楼梯中段前后轮同时抵住台阶沿、持续空转但不抬腿的问题，新增 `wheel_obstacle_lift` 多轮协调聚合逻辑。核心判断是当前 lift reward 对四个轮子独立触发并直接加和，容易让策略在多个轮子同时触障时缺少前后/对角分工信号，也可能鼓励同一组前轮或后轮快速连续大幅抬起。

本次不改触障检测、timer、target 和 lift 单轮 reward，只改最后的 reward 聚合方式。配置新增 `multi_wheel_coordination = True`，默认作用在楼梯 type 3 和高墙 type 9。当前聚合规则为：同一前轮 pair 或后轮 pair 同时 active 时，使用 `max_reward + residual * min_reward`，楼梯 residual 为 0.2，高墙 residual 为 0.4；四轮同时 active 时，使用对角组合 `FL+RR` 与 `FR+RL` 中更好的一组，并保留同样 residual。这样保留一部分未选中轮子的梯度，但明显降低“同组轮子一起抬都更赚”的收益。

预期效果是让策略在楼梯/高墙多轮触障时更倾向形成交替或对角分工，减少前后轮同时卡住空转，以及前轮/后轮一起大幅抬起的动作。风险是 reward 变稀疏后可能降低 lift 学习速度，或削弱高墙连续翻越能力；若高墙退化，可先提高 high-wall residual，或只在楼梯 type 3 启用该逻辑。下一轮重点观察楼梯中段是否仍出现前后轮同时抵边空转、正常上楼梯是否减少双前轮/双后轮大幅连续抬起、高墙是否保持稳定，以及 `rew_wheel_obstacle_lift`、`terrain_level`、`dof_pos_limits` 和 `wheel_obstacle_spin` 是否异常变化。
