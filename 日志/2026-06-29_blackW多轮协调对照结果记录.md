# 2026-06-29 blackW 多轮协调对照结果记录

## 1. Jun28_22-12-48_ 与 Jun28_22-14-55_ 训练结果初查

两组都从 `Jun26_12-30-56_` 继续训练到 34000 iter，使用新的 `wheel_obstacle_lift.multi_wheel_coordination` 聚合逻辑，并保持 `clearance_margin = 0.05`、`over_lift_margin = 0.03`、`wheel_obstacle_unloaded_lift = -0.05`、`wheel_obstacle_spin = -1.0`、`entropy_coef = 0.0032`。需要注意，两组实际保存的 `action_rate` 都是 -0.065，不是后续整理温和组时计划的 -0.06，因此这次对照不是完全原始 `Jun26_12-30-56_` 正则强度。

`Jun28_22-12-48_` 是温和 residual 组：楼梯 pair/diagonal residual 为 0.2，高墙 residual 为 0.4。`Jun28_22-14-55_` 是 B 组强 residual：楼梯 residual 为 0.0，高墙 residual 为 0.2。两组其余关键 obstacle 参数一致，因此主要对照的是多轮协调 reward reduction 强度。

末 500 iter 均值看，两个新 run 的 `rew_wheel_obstacle_lift` 都明显低于父 run `Jun26_12-30-56_`：温和组约 0.84，B 组约 0.79，而父 run 约 1.00。这符合 reward 聚合从四轮直接加和改为 pair/diagonal reduction 后的预期，不能简单按旧 lift 标量判断退化。`terrain_level` 两组约 5.56，略低于父 run 的 5.62；`progress` 基本持平在约 0.571；`wheel_obstacle_spin` 反而比父 run 稍轻。

B 组在若干稳定性指标上更干净：末 500 `value_function` 约 0.23，低于温和组约 0.26；`torques`、`action_rate`、`orientation` 和末 100 `dof_pos_limits` 也略好。但 B 组的 `mean_noise_std` 更低，末 100 约 0.305，温和组约 0.311，说明更强 reduction 下策略探索收敛得更快。当前不能只凭标量断定 B 组更好，因为它的 lift reward 被压得更强，关键仍要看 sim2sim 行为：是否减少双前轮/双后轮同时大幅抬起，是否改善楼梯中段前后轮同时抵边空转，以及高墙是否仍能顺畅翻越。

初步建议：先做 sim2sim 对照。温和组用于判断残差 0.2/0.4 是否已经足够改变动作时序；B 组用于判断更强 reduction 是否会进一步改善同步抬腿和卡住问题。若 B 组高墙或楼梯抬腿能力明显变弱，可考虑回到温和组或只对楼梯使用 B 组 residual、高墙保持 0.4。

## 2. Jun28_22-12-48_ 与 Jun28_22-14-55_ sim2sim 观察

sim2sim 观察显示，两组上楼梯相对之前都有一些改进，尤其是四个轮子同时碰到障碍时基本不会再卡住。这说明 `wheel_obstacle_lift` 的多轮协调聚合方向是有效的：四轮同时 active 时改用对角组合 reward，确实减少了所有轮子一起拿满 lift 奖励导致的同步卡死模式。

当前剩余问题更集中在后轮 pair：两个后轮同时碰到障碍后仍可能卡住，尤其在过高墙时更明显。这个现象和当前聚合逻辑也能对应上：四轮同时 active 时有对角 reduction，但只有后轮 pair 同时 active 时，目前只是 `max(rear) + residual * min(rear)`，并没有进一步要求后轮之间形成明确先后顺序，也没有奖励后轮接触后继续前向滚过障碍。因此策略可能已经避免了四轮同步卡死，但在高墙最后阶段，两个后轮同时抵住墙沿时仍缺少足够清晰的脱困信号。

暂不根据 sim2sim 继续改参数，先等待 sim2real 结果。实机观察重点：两组是否都减少四轮同时卡住；高墙后轮 pair 同时触障是否仍会卡住；B 组更强 residual 是否比温和组更能分开后轮动作，还是会削弱后轮抬腿/翻墙能力。如果实机也确认后轮 pair 是主要瓶颈，后续方向应优先考虑后轮 pair 的更强时序约束或后轮越障进度奖励，而不是再全局加大 lift height、spin 或 high-wall active time。

## 3. Jun28_22-12-48_ 与 Jun28_22-14-55_ sim2real 结果

sim2real 上楼梯结果与 sim2sim 基本一致：两组相比旧模型确实有好转，四轮同时触障卡死的问题减少，但仍会出现后轮卡住。两组中 `Jun28_22-12-48_` 的整体效果更好一些，说明温和 residual（楼梯 0.2、高墙 0.4）比 B 组强 residual 更适合当前策略；B 组虽然训练指标更干净，但实机行为不占优。

两个模型暴露出共同副作用：上楼梯时抬腿偏高，落地像砸向地面；同时两组都完全过不了高墙，甚至前轮也过不去。当前判断是多轮协调聚合虽然改善了四轮同步卡死，但默认同时作用在楼梯 type 3 和高墙 type 9 后，明显破坏了高墙所需的连续前轮抬起/翻越动作。高墙需要前轮有足够连续、强烈的 lift 信号去越过墙沿，而当前 pair/diagonal reduction 降低了多轮同时 active 时的总 lift credit，可能让前轮在触墙时拿不到足够收益，导致高墙能力直接丢失。

楼梯抬得过高则说明仅减少多轮同步奖励还不够，策略可能通过更高幅度的单轮/交替抬腿来弥补被削弱的 pair reward；加上当前楼梯 simple lift 不惩罚 over-lift，落地冲击会被放大。后续不应继续沿 B 组更强 residual 方向推进，也不应把多轮协调继续默认作用于高墙。

下一步建议：先将多轮协调限制到楼梯 type 3，关闭高墙 type 9 上的 coordination，恢复高墙原有 lift 聚合；同时优先以 `Jun28_22-12-48_` 的温和 residual 为基础，而不是 B 组。若继续优化楼梯落地冲击，可考虑恢复楼梯上的轻量 over-lift/落地冲击约束，或提高楼梯 residual，而不是继续压低 residual。高墙方向应单独处理后轮 pair 卡住问题，不能用同一套全局 pair/diagonal reduction 直接作用于高墙前轮翻越阶段。
