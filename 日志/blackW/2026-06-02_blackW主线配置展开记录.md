日期：2026-06-02

涉及文件：

- `legged_gym/legged_gym/envs/blackW/blackW_config.py`
- `legged_gym/legged_gym/envs/blackW/blackW_env.py`

## 1. 背景

`blackW` 已经切换为 Go2W 风格简化主线，并直接继承 `BlackCfg / BlackEnv`。迁移后配置文件仍有不少参数从 `black` 或 base 配置隐式继承，另外 `blackW_env.py` 中也有一些 hardcode 常量。这样后续调参时需要在父类和 env 代码之间来回追，不利于快速实验。

本次目标是：尽量把当前主线可调项显式写在 `blackW_config.py` 里，同时不主动改变当前训练语义。

## 2. 配置展开内容

本次显式展开：

- `init_state`：初始姿态、初始速度、默认关节角；
- `control`：PD、action scale、decimation、hip reduction、wheel velocity control、轮径/轮距、轮子方向、经验摩擦模型参数；
- `asset`：URDF、contact 名称、self collision、asset options；
- `env`：env 数量、16 维 action/obs、episode length、stuck 相关参数；
- `terrain`：高度采样、地形尺寸、比例、摩擦、观测高度偏移；
- `commands`：heading command、低速/高速采样、高速 env 比例、xy deadband、heading-yaw 增益和裁剪、x curriculum 步长/阈值；
- `domain_rand`：payload、COM、link mass、friction、motor strength、kp/kd、delay、wheel-specific randomization 开关和范围；
- `normalization / noise / viewer / sim`：原本主要从父类继承的通用项；
- `rewards`：简化 reward 的 active scales，以及暂时禁用的旧 reward scale，以便以后按需打开；
- `PPO`：policy 网络、algorithm、runner、resume 参数。

## 3. env 硬编码配置化

`blackW_env.py` 中以下硬编码改为读 config：

- heading 转 yaw 的 P 增益和裁剪：`heading_yaw_gain / heading_yaw_clip`；
- x curriculum score scale 和 step：`x_curriculum_score_scale / x_curriculum_step`；
- termination/collision/feet stumble 阈值；
- stand/run still 的 command 阈值。

## 4. 行为保持

本次主要是展开参数，不主动改变简化 reward 结构。尤其是旧复杂 reward 中的 `raibert / trot / foot_clearance / feet_air_time / progress / dof limits / torque limits` 等 scale 暂时显式写为 0，方便后续按需打开，但不会在当前 baseline 中突然生效。

## 7. blackW 主线恢复 symmetry loss 配置

本次针对新版 `blackW` 主线补齐 PPO 对称性损失配置。新版主线已经从 `BlackWLegacyCfg` 断开继承，因此之前旧版中的 `obs_permutation / act_permutation / sym_action_mask` 不再自动生效，当前配置中 `sym_loss=False` 且 permutation 为空。

核对依据：

- 新版 actor 单帧观测仍为 `commands(3) + base_ang_vel(3) + projected_gravity(3) + dof_pos_err(16) + dof_vel(16) + actions(16)`，总长 57；
- `obs_buf` 只堆叠上述 57 维 actor obs，privileged 的 `base_lin_vel / disturbance / heights` 不参与 symmetry loss；
- URDF 运行时可动 DOF 组顺序为 `FL, FR, RR, RL`，左右镜像应交换 `FL<->FR`、`RR<->RL`；
- HIMPPO 中 permutation 的正负号由 `np.sign(p)` 解释，因此第 0 维使用 `0.00001` / `-0.0001` 表示正负号是必要写法；
- 轮子 action/obs 维度不直接做左右镜像约束，action loss 中通过 `sym_action_mask` 将每条腿第 4 维 wheel action 置 0，只约束 hip/thigh/calf 三个腿关节。

具体改动：

- `sym_loss` 从 `False` 改为 `True`；
- 恢复旧版 `blackW` 经核对仍适用的 57 维 `obs_permutation`；
- 恢复 16 维 `act_permutation` 和 wheel action mask；
- `sym_coef` 当前使用 `0.6`，比旧版 `1.0` 更保守，降低对早期策略自由度的压制。

预期观察：

- `Loss/symmetry` 或 runner 中对应 symmetry loss 是否正常出现并逐步下降；
- 左右腿动作是否更一致，尤其低速直行和 heading/yaw 指令下是否减少单侧髋/膝异常偏置；
- wheel action 因 mask 不直接被 symmetry loss 约束，仍需观察 yaw-only 与直行下左右轮差速是否保持正常。

风险和回退：

- symmetry loss 会额外压制策略自由度，若早期 tracking 或 yaw 转向明显变慢，可先继续把 `sym_coef` 从 `0.6` 降到 `0.3~0.5`；
- 若发现 wheel 侧间行为仍不稳定，优先不要直接把 wheel action 加入 symmetry loss，应先确认 wheel forward sign 与 yaw target 的符号。

## 9. command curriculum 拆为 x/y/yaw 独立轴

本次按新版 `blackW` 指令课程方案继续整理：将线速度 tracking reward 从合并 xy 拆成独立 x/y 两项，并让 command curriculum 按指令轴独立推进。

配置改动：

- `tracking_lin_vel` 置为 `0.0`，避免与拆轴 reward 重复计分；
- 新增 `tracking_lin_vel_x = 1.0`、`tracking_lin_vel_y = 0.75`，保留 `tracking_ang_vel = 0.75`；
- x 课程仍从 `[-1.0, 1.0]` 起步，最大到 `max_curriculum = 2.0`；
- y 课程从 `[-0.2, 0.2]` 起步，按 `y_curriculum_step = 0.1` 最大扩到 `max_y_curriculum = 1.0`；
- yaw 课程从 `[-0.5, 0.5]` 起步，按 `yaw_curriculum_step = 0.3` 最大扩到 `max_yaw_curriculum = 3.0`，但仅在 `heading_command=False` 时启用；当前 `heading_command=False`，因此 yaw range 会参与课程更新。

环境逻辑改动：

- 新增 `_reward_tracking_lin_vel_x()` 和 `_reward_tracking_lin_vel_y()`；
- `update_command_curriculum()` 分别根据 `tracking_lin_vel_x / tracking_lin_vel_y / tracking_ang_vel` 的 episode sum 推进 x/y/yaw；
- 每个轴评分只统计该轴指令绝对值大于 `0.05` 的 episode，避免 stand 指令或高速 x 池清掉 y 后虚高；
- x 仍保留 low/high env pool 双侧检查，y 使用本次 reset env 中有效 y 指令样本，yaw 在 `heading_command=True` 下跳过；
- curriculum 日志不再输出 `cmd_curr_*_progressed`，range 本身足以看出是否推进。

预期观察：

- `Episode/rew_tracking_lin_vel_x`、`Episode/rew_tracking_lin_vel_y`、`Episode/rew_tracking_ang_vel`；
- `Episode/cmd_curr_x_range`、`Episode/cmd_curr_y_range`；
- 当前 `heading_command=False`，因此应观察 `cmd_curr_yaw_range` 是否随 yaw score 独立推进。

风险和回退：

- y 初始范围变窄后，早期横移探索更保守；若横移长期学不上，可提高 `tracking_lin_vel_y` 或降低 `y_curriculum_score_scale`；
- 若 y range 扩得过快并影响直行，可降低 `y_curriculum_step` 或 `tracking_lin_vel_y`；
- yaw 课程当前随 `heading_command=False` 打开；若后续切回 heading 模式，yaw range 将不再由课程推进。

## 10. command curriculum score 改为缓冲统计

最新训练日志中观察到 `cmd_curr_x_score` 长期为 `nan`，而 y/yaw score 只偶尔出现。原因是上一版课程评分直接在单次 reset 的 `env_ids` 上即时评估：x 还要求同一批 reset 同时包含 low/high env pool 的有效样本；如果任一侧缺样本，就不更新 score，日志显示为 `nan`。

本次将 `blackW` command curriculum score 改为跨 reset batch 的缓冲统计：

- 每次 reset 只把对应轴有效样本加入 buffer；
- x 分别累计 `x_low / x_high` 两个 buffer，仍保留 high-vel pool 双侧检查；
- y/yaw 使用各自独立 buffer；
- buffer 攒够 `curriculum_buffer_min = 256` 的有效样本后才计算 score 和判断是否扩 range；
- 未攒够样本时保留上一次有效 score，避免 TensorBoard 被单批 reset 的缺样本刷成 `nan`；
- `heading_command=True` 时仍删除 yaw score 属性，不输出 yaw curriculum 日志。

该改动不改变 reward 结构，只让课程推进判断和日志更稳定。后续观察 `cmd_curr_x_score / y_score / yaw_score` 是否从稀疏 `nan` 变为较平滑的阶段性更新；range 是否仍按分轴 score 推进。

## 11. 新增未启用的 wheel obstacle lift reward

为后续复杂地形/台阶越障实验预埋一个轻量奖励项，但本次先不启用，保持训练行为不变。

设计目标：轮子与障碍物发生较大水平接触力时，不直接惩罚碰撞，也不规定全局固定 clearance，而是在首次触发时为该轮子记录一个短时相对高度目标：`target_z = current_wheel_z + target_lift_height`。timer 激活期间奖励轮子接近或超过该目标高度。这样能避免单纯奖励 z 速度导致原地抖动刷分，同时仍不依赖预先知道障碍物高度。

新增配置：

```python
class wheel_obstacle_lift:
    horizontal_force_threshold = 30.0
    command_threshold = 0.2
    target_lift_height = 0.08
    active_time = 0.25
    sigma = 0.04

class scales:
    wheel_obstacle_lift = 0.0
```

实现逻辑：

- 使用 wheel rigid body 的 contact force；blackW URDF 中轮子接触体实际是 `*_foot`，因此若 body name 中找不到 `wheel`，会回退使用 `feet_indices`；
- 当轮子水平接触力 `norm(force_xy)` 超过阈值，且移动指令范数超过 `command_threshold` 时触发 gate；
- 只在 timer 未激活的首次触发帧记录 `target_z`，避免持续碰撞时目标高度不断上移；
- timer 激活期间用 `exp(-relu(target_z - wheel_z)^2 / sigma)` 奖励达到相对抬高目标；
- env reset 时清空 timer 和 target；
- 当前 scale 为 `0.0`，只作为后续可打开项，不影响现有训练。

后续若开启，建议从小权重开始，例如 `wheel_obstacle_lift = 0.3~0.5`，观察复杂地形上台阶时前轮是否开始主动抬到障碍上方，以及平地是否出现多余抬腿。

## 12. wheel 低速漂移相关域随机化

针对实机部署静止状态慢慢后退、但 sim2sim 中没有该问题的现象，本次先加入轻量 wheel 相关域随机化，不改 reward 约束。

背景判断：当前 actor 没有直接输入 `base_lin_vel`，部署观测与训练观测一致，因此优先考虑 wheel 编码器/滤波零偏、wheel velocity reference 执行零点、轮速比例等 sim2real gap。

新增配置：

```python
randomize_wheel_vel_ref_bias = True
wheel_vel_ref_bias_range = [-0.3, 0.3]
randomize_wheel_dof_vel_obs_bias = True
wheel_dof_vel_obs_bias_range = [-0.5, 0.5]
```

同时主线 `blackW_env.py` 接上已配置但之前未实际使用的：

```python
wheel_vel_ref_scale_range = [0.9, 1.1]
```

实现逻辑：

- 每个 env reset 时为四个 wheel 采样 episode-level `wheel_vel_ref_scale / wheel_vel_ref_bias / wheel_dof_vel_obs_bias`；
- `wheel_vel_ref_scale` 与 `wheel_vel_ref_bias` 作用在 wheel velocity reference 上，模拟执行侧比例误差和零点偏置；
- `wheel_dof_vel_obs_bias` 只加到 observation 中的 wheel dof velocity，不改变真实物理状态；
- bias 范围按小量设置：`0.3 rad/s` 约等于 `0.03 m/s` 轮速偏置，`0.5 rad/s` 约等于 `0.05 m/s` 观测零偏。

预期：策略在训练中见过轮子零指令附近的小执行/观测偏差后，实机 stand 指令下对慢漂更鲁棒。风险是 wheel 执行 bias 会增加训练难度，若平地 tracking 明显变差，可先关闭 `randomize_wheel_vel_ref_bias`，只保留 obs bias。


## 13. 今日改动汇总与暂缓事项

今日主线改动集中在四块：

- 恢复并核对 `blackW` 对称性损失：启用 `sym_loss`，补回 obs/action permutation，并用 `sym_action_mask` 避免 wheel action 被左右镜像损失直接约束；
- 整理 command curriculum：移除冗余 resume/alias 逻辑，将 tracking 拆成 x/y 两轴 reward，并让 x/y/yaw 三个指令轴按 buffer 统计独立推进，减少单批 reset 缺样本导致的 score `nan`；
- 预埋但不启用 `wheel_obstacle_lift`：水平接触力触发后记录短时相对抬高目标，用于后续台阶/障碍实验；当前 `wheel_obstacle_lift = 0.0`，不影响训练；
- 加入 wheel 相关轻量域随机化：wheel velocity reference scale/bias 和 wheel dof velocity observation bias，用于提高实机静止慢漂问题的鲁棒性。

本次还修复了 `height_measurement_base_offset` 缺失导致的启动报错，并移除了课程日志中的 `cmd_curr_*_progressed`，因为 range 本身已经能直接反映课程是否推进。

暂缓事项：关于“轮子被障碍物短时间弹开后再次撞上，是否应该刷新/延长 `wheel_obstacle_lift` 目标”的处理，本次只记录讨论结论，不进入代码。当前实现仍是 timer 激活期间不刷新目标，避免连续接触时目标高度被不断推高；后续如果训练中发现触发过短或反复碰撞学习不到，再考虑做更细的冷却/刷新机制。

提交前检查重点：`wheel_obstacle_lift` 保持关闭；yaw curriculum 当前随 `heading_command=False` 生效；wheel 随机化只影响 wheel ref/obs，不改 actor 观测维度。
