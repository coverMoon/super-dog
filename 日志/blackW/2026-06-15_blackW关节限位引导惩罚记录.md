# 2026-06-15 blackW 关节限位引导惩罚记录

## 1. dof_pos_limits 改为接近限位二次引导

背景：此前 blackW 覆盖 _reward_dof_pos_limits 后只统计非轮腿关节，并在真正越过 URDF 限位后才产生线性惩罚。该设计能避免轮子连续转动污染 reward，但对训练早期或 calf backlash 放大后的极限姿态补偿缺少提前引导。

实现：保留只统计 leg_dof_indices 的逻辑，继续排除 wheel_joint；新增 rewards.dof_pos_limit_margin_ratio = 0.10。当 hip/thigh/calf 距离上下限小于关节范围 10% 时，按归一化距离产生二次惩罚：安全区为 0，越靠近限位越大，越限后继续增长。若 margin ratio 设为 0，则回退到原来的越限线性惩罚。

配置：由于惩罚从“越限才触发”变为“接近限位也触发”，将 rewards.scales.dof_pos_limits 从 -0.5 降到 -0.05，作为姿态卫生引导项，而不是硬约束。

预期观察：rew_dof_pos_limits 应从几乎全 0 变成小幅稳定负值，理想量级约 -0.001 到 -0.03；同时关注 terrain_level、rew_wheel_obstacle_lift、rew_base_height、rew_lin_vel_z、rew_torques 和 rew_smoothness。若越障或 base height 变差，优先将权重降到 -0.02 或将 margin 降到 0.05；若该项仍几乎为 0 且极限姿态未改善，再考虑权重提高到 -0.08 或 -0.1。


## 2. Jun15 渐进续训路线结果记录

对 Jun15_16-20-45_、Jun15_18-40-46_、Jun15_21-24-51_ 复查后，当前判断：加大 calf play 虚位范围并叠加 dof_pos_limits 接近限位引导这条路线本身可行。Jun15_13-01-56_ 的崩溃更可能来自 yaw curriculum 推得过快，同时叠加 action_rate 加重，而不是 dof 限位引导或 calf 虚位随机化单独导致。

三次稳定续训路线如下：Jun15_16-20-45_ 从 Jun13_22-07-48_ 续训到 26000，将 yaw_curriculum_score_scale 恢复为 0.6，action_rate 使用 -0.07，calf_backlash_range 为 [0.005, 0.035]，calf_backlash_min_kp_scale 为 0.12，dof_pos_limits 为 -0.08；Jun15_18-40-46_ 从 26000 续到 27000，只将 action_rate 加到 -0.075；Jun15_21-24-51_ 从 27000 续到约 27800，将 action_rate 加到 -0.08，并将 dof_pos_limits 加到 -0.1。

曲线表现稳定：三次末段 mean_episode_length 约 965 到 973，mean_reward 约 56 到 58，terrain_level 约 5.63 到 5.66，value_loss 约 0.18 到 0.21。rew_smoothness 维持约 -0.11，rew_torques 约 -0.39，rew_lin_vel_z 约 -0.04，没有出现 Jun15_13-01-56_ 中 smoothness、torques 和 value loss 链式爆炸。rew_dof_pos_limits 稳定在约 -0.02 到 -0.027，说明接近限位引导处在可接受量级。

后续若继续加大虚位，建议保持 yaw curriculum 不动，优先单变量试 calf_backlash_range 从 [0.005, 0.035] 到 [0.005, 0.04]，不要同时放大 yaw 课程或进一步加重 action_rate。


## 3. 高墙前腿翻越时对角后腿跟抬的代码探查

现象回顾：高墙场景中，前腿/前轮抬起翻越时，有时对角后腿也会过早跟着抬起。此前已记录过轻量抑制方案，包括前轮触墙早期窗口内轻罚对角后轮过早抬起、多轮同时抬起抑制等。本次先不改代码，只检查当前配置中可能诱发现象的项。

当前主线仍启用 PPO symmetry loss，sym_loss 为 True，sym_coef 为 1.0。动作对称映射按左右镜像交换 FL 与 FR、RL 与 RR，sym_action_mask 排除了四个 wheel action，但 hip/thigh/calf 三个腿关节 action 都参与 symmetry loss。该项不会显式要求前腿和对角后腿同步抬，但会压低左右镜像状态下腿部动作差异，可能让策略更偏好成对、镜像一致的腿部响应；在高墙触发这种局部非对称事件时，它是值得怀疑的隐性耦合来源。若要验证，可单独跑 sym_coef 从 1.0 降到 0.5 或在高墙后期 checkpoint 上做短续训对照。

当前 blackW 主线中 trot、raibert、foot_clearance、feet_air_time 等显式步态/相位奖励 scale 都为 0，因此它们目前不像导致对角后腿跟抬的直接原因。旧版里这些项会强制对角步态，但当前主线已关闭。

wheel_obstacle_lift 当前是逐轮触发、逐轮 timer、逐轮目标高度；new_trigger 使用每个 wheel 的水平接触力、前方障碍高度和 command gate 独立判定。代码上没有显式要求对角后腿同步抬起。不过该奖励只奖励被触发轮抬高，不惩罚未触发轮的无关抬高；再叠加全局 action_rate、smoothness 和 symmetry loss，策略可能学到“前轮处理高墙时带动一组腿一起变化”也不亏。

全局 action_rate 和 smoothness 对所有 action 做统一平方惩罚，不区分触墙轮和非触墙轮。它们通常会抑制乱动，但也可能鼓励策略复用平滑的全身模板，而不是非常局部的单腿动作。当前 action_rate 已逐步加到 -0.08 且训练稳定，若 sim2sim 仍有对角后腿误抬，不宜先继续加重 action_rate；更应该优先验证 symmetry 或增加局部上下文抑制。

高墙/困难地形命令并非完全 x-only。当前 terrain_command_sampling 对 difficult terrain 使用 lin_vel_y 和 ang_vel_yaw 的窄范围 [-0.5, 0.5]，heading_command_difficult_only 也会让困难地形进入 heading/yaw 逻辑。高墙中带 y/yaw 的样本会增加全身姿态协调压力，可能放大腿部耦合；但它更像背景难度来源，不是对角后腿跟抬的最直接机制。

当前更可疑的排序：第一是 symmetry loss 对腿部动作的镜像一致性约束；第二是 wheel_obstacle_lift 只奖励触发轮、不惩罚无关轮抬高；第三是全局 action/smoothness 正则促成全身模板化动作；第四是困难地形仍有 y/yaw 命令带来的姿态耦合。建议先做只改 sym_coef 的短对照，或实现前轮触墙早期窗口内对角后轮轻惩罚时，将权重设得很小并只在高墙/障碍接触上下文生效。


## 4. 高墙前轮触发早期对角后轮误抬轻惩罚

基于前一节代码探查，本次采用方案 A：只在高墙地形中，对前轮触墙/障碍触发 wheel_obstacle_lift 后的早期窗口，轻罚对角后轮过早抬起。目标是抑制前腿翻越高墙时对角后腿跟随误抬，但不阻碍后轮随后真正接触并翻越障碍。

实现：在 wheel_obstacle_lift 现有逐轮 timer 基础上新增 wheel_obstacle_lift_elapsed，用于记录每个轮子的 lift 事件已持续时间；reset 时同步清零。根据 wheel body 前缀建立前轮到对角后轮映射：FL 对 RR，FR 对 RL。新增 reward 项 wheel_obstacle_rear_suppress，名字刻意放在 wheel_obstacle_lift 之后，保证同一轮 reward 中先更新 lift timer/elapsed，再计算抑制项。

触发条件：terrain type 必须是高墙 9；FL 或 FR 的 wheel_obstacle_lift_timer 正在 active，且 elapsed 小于等于 diag_rear_lift_suppress_time；对应对角后轮自身 lift timer 未 active；对角后轮高度超过 ground + wheel_radius + diag_rear_lift_suppress_height 后，按超出量除以 diag_rear_lift_suppress_sigma 做二次惩罚。

配置：diag_rear_lift_suppress_time = 0.3s，diag_rear_lift_suppress_height = 0.05m，diag_rear_lift_suppress_sigma = 0.05m，rewards.scales.wheel_obstacle_rear_suppress = -0.02。该项只作为很轻的局部提醒，不作为硬约束。

预期观察：TensorBoard 会新增 rew_wheel_obstacle_rear_suppress。若 sim2sim 中对角后腿提前跟抬明显减少，同时 high wall 通过率、rew_wheel_obstacle_lift、rew_torques、rew_base_height、rew_lin_vel_z 和 value_loss 不变差，则该方向有效。若高墙通过率下降或后腿真正该翻越时被压住，优先把 scale 降到 -0.01，或把 suppress_time 从 0.3 降到 0.2；若该项几乎没有量级且现象仍明显，可将 suppress_height 降到 0.04 或 scale 提到 -0.03。


## 5. 对角后轮误抬抑制与 symmetry 降权对照计划

基于高墙前轮翻越时对角后轮跟抬现象，当前准备跑两个对照实验。A 组开启 wheel_obstacle_rear_suppress，保持 symmetry loss 配置不变；B 组关闭 wheel_obstacle_rear_suppress，同时降低 symmetry loss，用于区分局部接触上下文抑制与全局左右镜像约束降权两种机制的效果。

A 组当前配置：rewards.scales.wheel_obstacle_rear_suppress = -0.08，sym_loss = True，sym_coef = 1.0。该抑制项只在高墙地形、前轮 wheel_obstacle_lift 触发早期、对应对角后轮自身 lift 未 active 时生效；对角后轮超过 ground + wheel_radius + 0.05m 后按 0.05m sigma 二次惩罚。-0.08 比最初 -0.02 强 4 倍，属于可见但仍局部的中等约束；若单轮超过允许高度 5cm，raw penalty 约 1，对总 reward 贡献约 -0.08。

B 组建议配置：将 rewards.scales.wheel_obstacle_rear_suppress 置 0，保留代码但关闭该项；将 sym_coef 从 1.0 降到 0.5，其他训练参数尽量保持与 A 组一致。这样可以观察对角后腿跟抬是否主要来自 symmetry loss 对腿部动作的镜像一致性约束。

建议两个实验都从同一个稳定 checkpoint 分叉，例如 Jun15_21-24-51_ 后段模型，短训 500 到 1000 iter。观察重点：sim2sim 中高墙前轮触墙/翻越早期对角后腿是否仍提前抬起，高墙通过率、rew_wheel_obstacle_lift、rew_wheel_obstacle_rear_suppress、rew_torques、rew_smoothness、rew_base_height、rew_lin_vel_z、value_loss 和 terrain_level。若 A 组抑制明显且通过率不降，则优先保留局部抑制；若 B 组同样改善且动作更自然，可考虑降低 sym_coef 作为更简洁方案；若两者都改善，可再尝试小权重组合。
