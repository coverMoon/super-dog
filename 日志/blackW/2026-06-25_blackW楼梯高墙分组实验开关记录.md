# 2026-06-25 blackW 楼梯/高墙分组实验开关记录

## 1. 上楼梯 Jun06 风格逻辑开关

为便于从 Jun06 模型继续训练并同时对照当前高墙/平地优势，本次不新增 reward 项，只给现有 `wheel_obstacle_lift` 和 `wheel_obstacle_spin` 加两个配置开关：

- `rewards.wheel_obstacle_lift.stairs_use_simple_lift`：默认 `False`。开启后仅在上楼梯 terrain type 3 中使用 Jun06 风格简化抬轮逻辑：目标高度为障碍高度加 clearance，active time 固定，target error 只罚未抬够，不使用高障碍额外目标/额外 active time/过抬惩罚。高墙 type 9 仍走当前复杂 lift 逻辑。
- `rewards.wheel_obstacle_spin.stairs_use_threshold_spin`：默认 `False`。开启后仅在上楼梯 terrain type 3 中使用 Jun06 风格硬阈值空转惩罚，其他地形继续使用当前连续滑差惩罚。

原建议三组实验：A 组两个开关均关，作为当前逻辑基线；B 组只开启 `stairs_use_simple_lift`，隔离抬轮逻辑影响；C 组两个开关都开启，测试楼梯 lift/spin 同时回 Jun06 风格是否能保留 Jun06 上楼梯不前顶的优势。

观察重点：上楼梯前轮触台阶后 base/重心是否继续前挤、倾倒率、楼梯通过率、`rew_wheel_obstacle_lift`、`rew_wheel_obstacle_spin`、高墙通过姿态、平地速度跟踪和动作平滑。若原 B 组已明显改善，优先保留 lift 解耦；若原 C 组进一步改善，说明当前连续 spin 也在改变楼梯接触节奏。

## 2. 实际排期调整：只跑两组

考虑一张卡一次只能跑两组，且当前配置已经与前序表现存在偏移，原 A 组“两个开关均关”的基线意义不大，容易只是在验证当前配置是否已经把之前表现掰歪。本轮先不跑原 A 组。

当前实际对照改为两组：

- 当前 A 组：对应原 B 组，只开启 `stairs_use_simple_lift`，用于观察仅回退上楼梯抬轮逻辑是否能缓解前顶/前挤。
- 当前 B 组：对应原 C 组，同时开启 `stairs_use_simple_lift` 和 `stairs_use_threshold_spin`，用于观察 lift 与 spin 都回 Jun06 风格时是否进一步改善楼梯接触节奏。

后续比较时注意组名已经重排：当前 A/B 分别对应原计划 B/C，不再包含原计划 A 基线。若两组都不理想，再考虑单独补跑两个开关均关的当前逻辑基线作为定位参考。

## 3. 删除上楼梯额外 run_still，整理高墙无载抬轮命名

根据当前实验判断，之前为抑制上楼梯前倾/重心前移而加入的 `stairs_run_still` 额外关节回中奖励暂时用处不大，且可能继续改变 Jun06 风格楼梯动作。本次删除 `rewards.scales.stairs_run_still`、`stairs_run_still_terrain_types` 与 `_reward_stairs_run_still`，保留全局 `run_still = -1.0` 作为基础直行姿态约束。

同时将 `wheel_obstacle_rear_suppress` 改名为 `wheel_obstacle_unloaded_lift`。当前实现早已不是只压“对角后腿”，而是在高墙地形中惩罚未触发自身 lift、水平接触力较小的轮子凭空抬高；同步将配置字段改为 `unloaded_lift_suppress_height/sigma`，删除旧的 `diag_rear_lift_suppress_*` 命名残留和不再使用的 lift elapsed/对角轮索引维护。行为目标不变，只让 TensorBoard 名称和代码语义对齐。

预期观察：TensorBoard 不再出现 `rew_stairs_run_still`，`rew_wheel_obstacle_rear_suppress` 改为 `rew_wheel_obstacle_unloaded_lift`。重点看上楼梯前轮触台阶后的前顶/前挤是否因少了额外回中约束而变自然，同时关注楼梯通过率、`rew_run_still`、`rew_wheel_obstacle_lift`、`rew_wheel_obstacle_spin`、高墙无关轮误抬、高墙通过姿态和动作平滑。
